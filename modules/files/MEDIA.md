# Media content and calendar contract

TreePane loads MediaContent only while media mode is active. Ordinary mode has no media provider, grid, thumbnail cache or timeline instance, and no media filtering or calendar geometry bindings. Leaving media mode destroys that subtree and cancels its outstanding work. Retiring the Files view on blade close also cancels its provider; reopening reads the current location. Teardown does not reconcile selection against a cleared media model. Inactive providers ignore root, capability, filter-scope and backend-readiness changes until activated.

Media uses cached backend `children-window` pages of 400 entries, one request at a time. Scope starts at the current folder. Recursion is explicit and skips directory symlinks. Listing stops with a visible partial-scope notice at 100,000 entries or 4,096 descendant directories; backend caps are also exposed. Media recognition includes MIME and suffix fallbacks. Recognition is separate from decoder support: unsupported or corrupt images and videos stay visible. Comprehensive decoding and explicit playback belong to tasks 6.2 and 6.3 and are not complete here.

The existing selection controller receives the media model and exact paths. Query and metadata filters remove hidden action targets. Query, recursion and size are per view; the ordinary query and location/history remain intact. A supplied location descriptor requires explicit capabilities; the existing local provider path is retained while the Locations integration is pending. No arbitrary URI becomes a POSIX path.

`MediaDates.normalize(value, precision)` accepts provider dates, including `{value, precision}`, epoch seconds/milliseconds, calendar years/months/days, and ISO timestamps with offsets. The existing local provider supplies cached local mtime strings. An explicit offset is converted into the local calendar. Date-only values are not interpreted as UTC. Precision can reduce the known calendar fields; it never invents fields absent from the input. Invalid or explicitly unknown records are Undated. Calendar arithmetic uses day ordinals, independent of daylight-saving day length. An optional numeric timezone offset is available for deterministic tests; the UI omits it and uses local time.

`MediaDates.localeRule(Qt.locale().name, Qt.locale().firstDayOfWeek)` uses Qt's resolved locale and first weekday. Qt's QML locale interface does not expose minimum days in the first week; the territory minimum-days table is the Gregorian `weekData/minDays` subset from Unicode CLDR release 48. Default territory 001 uses one day, and the listed territories use four. First weekday and minimum days are independent: Portugal and Iceland are examples of Sunday-start/four-day rules. Week-year follows those same two inputs. A system change takes effect when the runtime's locale is refreshed or restarted.

Source: https://github.com/unicode-org/cldr/blob/release-48/common/supplemental/supplementalData.xml#L4676-L4696. The retained Unicode-3.0 license is [CLDR-LICENSE](CLDR-LICENSE). No new runtime dependency or network request is needed.

`MediaBins.records` normalizes once per input change. `build(records, level, parent, rule)` returns bins with half-open day bounds and exact source indices. All marks at a level share the returned maximum count. Empty calendar periods remain present; limited precision goes into a counted unknown-precision child when membership in finer bins cannot be established. Undated is the final overview bin. Child weeks and days are clipped to parent bounds. Histories over ten years initially coarsen to years; fine week/day bins require a month/week parent. `ordered` gives the main view a stable chronological model, with unknown day precision at the end of its month, unknown month precision at the end of its year, and Undated last. It retains original order for equal dates and never merges files into private variant stacks. An explicit PaneView sort instead applies the existing TreeOrder comparator to all matching rows across pages, including name, size, dates and secondary sorts. Stable exact-path ties keep page arrival order from deciding equal sort values. The backend continues to enumerate stable name pages; changing the sort does not re-enumerate media. The selected path and current first visible tile are independently retained through reordering.

`MediaTimeline` chooses months when all marks fit at least 18 scaled pixels per target; otherwise it uses years. Year-only records also start at years so they never imply a month. Extremely long spans aggregate adjacent years into counted ranges, which drill through smaller ranges to individual years. Every level shares one maximum count. A child is unavailable if it cannot fit readable targets in the available height. Changing scope or query resets detail; ordinary media scrolling does not.

Bin geometry comes from the actual grid columns, row pitch and tile height. A bin stores the exact contiguous row intervals containing its ordered indices; adjacent periods sharing a tile row both intersect that row. For name/size or descending date order, separated intervals remain separated: scrolling through a gap never lights a period whose items are elsewhere. Binary search finds visible intervals and seek positions without scanning all files on each scroll. The axis stays chronological even when the content has an explicit non-date order; its outline is the calendar extent of visible content, not a second linear scrollbar. The viewport projects its first and last partial bin intersections onto one square outline, including intervening empty calendar gaps. Counts are independent of selection. No file metadata is read during scrolling. Blue roles are centralized on MediaTimeline: lightBlue #89b4fa and darkBlue derived at 2.25 darkness; the later shared design-token gate must account for these explicit semantic colors.

The header names the current period and detail. Down enters the last explicitly navigated period, otherwise the first visible period; Up returns to its parent. Timeline-focused Left/Right are coarser/finer; Up/Down and Home/End seek nonempty periods. The buttons expose accessible names and support Space/Return. Browser modified arrows and Escape retain their existing handlers. Pointer presses on a count interval seek immediately; dragging the sole outline retains the grab offset. Empty intervals are inert. Seek cancels existing flick momentum and assigns contentY without selecting files, changing the query, filtering the model, animation, flashing or hover decorations. The legacy ImageGrid/TimelineScrubber used by Goblins is unchanged.

## Guest scenarios

Build the runtime binary with the lane's prescribed Cargo command, then stage with `ovm push` in harness B. Prepare the guest-only read-only probe with `python3 <guest-plugin>/tests/vm/fixtures/media.py prepare /tmp/brindle-media`, then restart the guest shell. Run `tests/vm/expectations/50-media-mode.sh` with `OVM`, `OVM_HOME` and `OVM_SSH_PORT` set to harness B. The script recreates its fixtures each run, including after a guest cold boot. Restore the original guest TreePane with the fixture's `restore` action after testing; probes are never shipped in application code. Restore ordinary mode and standard pane fractions before running the older coordinate-based suites.

Run scenario scripts with `bash`: 50-media-mode.sh covers 14 media-mode checks; 51-media-wheel.sh uses a real pointer and Space to drop a media tile on the wheel hub; 52-media-timeline.sh covers count/drill/seek/width behavior; 53-media-parity.sh tests shared sorts across pages, independent selection/anchor retention, VISUAL and Shift arrows, and browser Back from timeline focus. The timeline scenario also injects explicitly synthetic provider dates into the guest-only probe to exercise month-only, Undated and very long histories against actual PNG paths. Restart the guest shell after 52 to restore the production items binding. These fixtures are not decoder-format or performance evidence.

## Size control

The default Files layout places an informational folder/repository summary between search and navigation. It reuses `PaneRow`, `FileIcons` and `GitSummary`, with no caret, click action or selection target. The per-view **Summary in tree** setting restores the original interactive root row and persists across restart. Controller indices stay unchanged; the relocated root delegate has zero height and is excluded at this pane’s own keyboard and pointer selection boundaries. Explicit shared IPC or extension selection of the directory remains valid; relocation only clears the local hidden-row cursor. Empty informational scopes reject selection-dependent keyboard menus, while new-file/new-folder actions pass the current directory explicitly as their destination. Collapse-all keeps the informational root expanded while collapsing its child folders. Both placements use the existing count/density footer and essential host footer actions.

`59-media-summary.sh` checks repository identity/status, inert clicks, root exclusion from navigation/select-all/ranges, collapse-all, the actual settings toggle, restart persistence, narrow placement, empty folders and the shared media summary/footer. It also checks shared select/selectEntries retention, pointer range exclusion, physical Menu/F2 refusal for the hidden root, explicit empty-folder creation destinations and restored root menus in tree placement. It uses the existing disposable media probe in harness B.

`DensitySlider` is a five-stop control with a straight track, a 28-pixel scaled thumb hit target and the Omarchy U+E900 mark from the `omarchy` font used by the shell’s menu widget. Its centre is filled. The focused control handles arrows, Home/End and plus/minus without replacing itself during grid reflow. `ImageSizeControl` remains its compatible media facade: `step`, `shortcutSmaller`, `shortcutLarger`, `steps`, `clamped`, `stepRequested(int)` and `request(next)` retain their meaning. The additive `keyPressed(var event)` signal forwards other keys to the files pane; unhandled keys still bubble to existing parent consumers. Implicit dimensions are now 156 by 28 scaled pixels. The media stops remain 56/84/120/168/240, with M as default and names at L/XL. Ordinary rows use the separate factors 0.85/0.925/1/1.075/1.15, persisted as ordinaryDensityStep per Files view. The same control changes row height and font/icon sizes; it preserves the first-visible path and selection. Current-folder footer counts read cached immediate children and a paging total, excluding expanded descendants and the root row. Counts update on coalesced tree completion/structure notifications rather than through a binding to each inserted row. ViewChrome retains one result per live model in a WeakMap, keyed by root path, row count and structure/row revisions. Reopening an unchanged view only checks root readiness; it does not scan the listing again. Unready/error roots discard the cached value, including role changes without a revision. Root, filter and hidden-scope changes invalidate the value; collapsed, unready or failed listings show Count unavailable. A loaded empty folder shows zero. Density changes retain the proportional position within the first visible row; rapid changes share one pending anchor. Active drag-wheel keys take precedence, followed by configured tree bindings, then the ordinary density fallback.

`54-media-slider.sh` drives a real continuous thumb drag through all five positions, checks focus and selected-path retention, focused keys and boundary clamping, narrow-blade plus/minus media-size retention through a mode round trip, and browser Back/Escape while focused. The direct `tst_media_slider.qml` suite additionally checks independent instances, fractional/nonfinite request compatibility and drag ownership outside the track. This does not qualify native popouts or the separately maintained Goblins renderer.

`55-media-density.sh` checks rendered ordinary row heights, focused controls, the largest density jump’s scroll anchor, selected paths, an independent production BladePopout context, per-mode state, narrow width, restart persistence and ordinary minus. The popout is created hidden by the disposable guest probe to verify independent state, not native window placement or painting.

`56-media-lifecycle.sh` verifies the media subtree is absent during ordinary navigation/reopen, mode entry reads the current folder, blade retirement preserves selected identity, leaving media destroys its provider and view, and reentry cannot show rows from an earlier location. The provider unit suite additionally rejects inactive state resets and backend-ready scheduling, and checks cancellation of the original request owner.

`57-media-chrome.sh` covers coalesced count updates, collapsed and paged roots, navigation, hidden/filtered/empty scopes, partial ordinary and path-visible search rows in both size directions, rapid changes and explicit minus bindings. `58-media-wheel-keys.sh` supplies plus/minus keys through the existing supported custom wheel-entry callback seam during real ordinary-row drags, verifies one exact-path activation with unchanged density, and then verifies the inactive-wheel density fallback. It tests the key consumer; R32 configuration-file parsing belongs to wheel integration.
